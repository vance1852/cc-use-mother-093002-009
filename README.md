# 分配人工智能普惠支持协作基础服务

本项目提供跨境数字贸易合作业务共享的服务端基础能力，负责合作机构、业务节点、操作者和结构化参考资料的登记，内置角色权限、请求幂等、SQLite 事务与哈希串联审计。各领域模块可以在这些稳定边界上扩展自己的状态、规则和接口。

## 目录

- src/digital_trade_foundation/：领域模型、SQLite 存储、权限服务、审计链、HTTP 路由和离线验收；
- src/inclusive_support/：普惠支持资格、配额与成效跟踪领域模块（政策版本、关联去重、评审回避、排序、限时预留、分期、里程碑、效果指标、退出释放、特批会签与成效比较）；
- tests/：基础规则、事务边界、接口路由、普惠支持规则、重启恢复和端到端验收测试。

## 普惠支持模块

`inclusive_support.SupportService` 继承基础服务，在同一 SQLite 数据库上扩展业务表，并复用其操作者、角色、幂等回执与审计链：

- 政策版本由管理者登记并冻结，冻结后的配置（预算、地区优先级、支持类别权重、数字基础条件权重、必要材料、前置里程碑、分期计划、效果指标、预留时限）是排序与额度决策的唯一依据；
- 申请主体登记受益关系键，排序时按关联组去重，每组只保留得分最高的申请；评估人员与服务商的利益关系必须事先申报，评审与核验时强制回避；
- 排序按冻结配置计算得分（地区档位分 + 基础条件需求分 + 类别分），同分按申报时间与编号稳定排序，得分构成逐条落库，可以复核；
- 入选申请获得限时预留，只有补齐必要材料并通过前置里程碑核验才能转为正式承诺，承诺按分期计划生成额度，里程碑核验通过后逐期拨付；
- 放弃、逾期、局部失败或预算缩减会释放未兑现部分（生效预留与未拨付分期），并沿冻结排序产生的稳定候补继续分配；已完成且核验通过的支持不参与重排；
- 特批由管理者发起、独立会签人（审计角色，且不能是提案人）会签，响应中给出对地区公平性的影响（各地区份额与最大份额差的变化）；
- 申报、材料、服务商里程碑回调等写入均按 request_id 幂等，重放返回原回执与原响应，不会重复占用额度；
- 预留到期时间、候补顺序与分期余额全部落库，服务重启后继续准确；管理者可按政策版本查询每次获配或落选的原因，并比较资金覆盖、地区分布与有效成果。

角色分离：admin 管理政策、预算、排序、退出与特批提案；operator 登记主体与服务商、申报、补材料、里程碑与效果回调、撤回；reviewer 申报利益冲突、评审、核验里程碑与效果；auditor 独立会签特批。

## 环境

- Linux
- Python 3.11 或更高版本
- 运行时仅使用 Python 标准库和 SQLite

## 测试

    PYTHONPATH=src python3 -m unittest discover -s tests -v

## 构建检查

    python3 -m compileall -q src tests

## 离线验收

    PYTHONPATH=src python3 -m digital_trade_foundation.acceptance
    PYTHONPATH=src python3 -m inclusive_support.acceptance

基础服务验收会在临时 SQLite 数据库中登记合作机构、操作者、业务节点和参考资料，核对幂等回执与审计链；普惠支持验收会跑通关联去重、评审回避、冻结排序、限时预留转承诺、分期拨付、效果核验、特批会签与退出释放的完整链路。两者成功时都输出一行 status 为 ok 的 JSON 并以退出码 0 结束。

## HTTP 服务

    PYTHONPATH=src python3 -m digital_trade_foundation.api --database digital_trade.sqlite3 --host 127.0.0.1 --port 8080
    PYTHONPATH=src python3 -m inclusive_support.api --database support.sqlite3 --host 127.0.0.1 --port 8081

健康检查使用 GET /health。写入接口通过 X-Actor-Id 标识操作者，服务重启后 SQLite 中的业务状态和审计历史继续保留。普惠支持接口挂在 /support/ 前缀下（政策、申请、评审、排序、承诺、里程碑、效果、特批、报告与比较），未命中的路径回落到基础服务路由。
